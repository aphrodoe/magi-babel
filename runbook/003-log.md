## 2026-09-03 · same day as H-02 closing
- **Did:** The whole software half of H-03 in one sitting. Metrics first — Prometheus,
  node_exporter, cAdvisor, Grafana on a new `glass` network, with Grafana and Prometheus
  also on `edge` so Caddy can serve them at `grafana.` and `prom.lab.akhildhyani.me`.
  node_exporter is the one container in the host network namespace, because `/proc/net`
  is per-namespace and a bridged exporter reports its own interfaces no matter how much
  of the host's `/proc` you mount at it. Then logs — Loki + Alloy (not Promtail, EOL
  March 2026), tailing both the docker socket and journald; the journal is the half that
  matters, since `magi-netaccess`'s portal retries and wpa_supplicant's slow PEAP
  association never appear in `docker logs`. Then Uptime Kuma, probing the *public*
  hostnames rather than container names, so it fails on a dead cert or a lapsed DNS
  delegation — things `magi-sys.py` cannot see. Datasources and dashboards provision
  from files (R1); two grafana.com dashboards committed with `__inputs` stripped and the
  datasource pinned to `uid: prometheus`. `whoami` retired, as H-03 said it would be.
- **Broke:** node_exporter's scrape timed out through two rounds of fixing. First cause:
  ufw's default-deny drops packets arriving from a docker bridge bound for the host, and
  *every layer looks fine in isolation* — the exporter logs "Listening on
  100.94.219.53:9100", `ss` shows the socket, `curl` from the host returns 200, ufw's own
  status shows nothing wrong. Second cause, mine: the rule I wrote named `br-glass`, but
  Prometheus is on both `glass` and `edge` and Docker routed it out `edge`, so the rule
  never matched. `[UFW BLOCK]` in the kernel log names the interface a packet actually
  arrived on and ended the argument in one line. Separately, pinning the Grafana
  datasource's uid crash-looped Grafana: provisioning cannot repoint an existing
  datasource at a new uid, and Grafana exits rather than run a half-applied config. And I
  put two errors into my own `MONITORS.md` — a probe target of `1.1.1.1`, which CLAUDE.md
  forbids precisely because on campus wifi that address is the DHCP server and the probe
  would pass while the portal was dead, and a Loki probe from a container that wasn't on
  `glass`.
- **Differently:** Set a provisioned uid before the first start, never after — changing
  one costs a crash loop and a `deleteDatasources` block. Before writing an
  interface-scoped firewall rule, check which network the container actually egresses
  from; a multi-homed container picks one and it may not be the one you had in mind. And
  reach for `journalctl -k | grep "UFW BLOCK"` first, not third: I spent two rounds
  reasoning about whether ufw or Tailscale's `ts-input` chain was responsible when one
  grep answered it.

## 2026-09-07 · H-03 closes
- **Did:** Paid off the dashboard walkthrough owed from 03 Sep, then closed the phase.
  The walkthrough was built by querying MAGI rather than describing Node Exporter Full
  generically, which is what surfaced four readings that look like faults and aren't:
  RAM total is 6.93 GiB not 8, because the Iris Xe reserves ~1 GiB before Linux sees
  it; 4.85 GiB of that is reclaimable cache, so "used" reads ~76% when the honest
  figure is ~24%; `node_network_up` reports `tailscale0` **down** while it carries
  every SSH session to the box, because a TUN device has `operstate=unknown` and the
  exporter maps anything not `up` to 0; and `br-glass` reads 0 B/s in both directions
  while the whole stack talks over it, because a bridge counts only what crosses it to
  the host, never frames it forwards port-to-port. Written up as `dashboards/READING.md`
  with the idle baseline, since a reading only means something against what this box
  normally does. Then the panel: **deferred to H-05.** Four of its six numbers don't
  exist yet (ADS-B, satellite pass, last backup, deck status all land in later phases),
  and the display hangs off the same ESP32-S3 that H-05 mounts and wires for the strip —
  one wiring session instead of two. H-03 therefore closes on software.
- **Broke:** Changed two places out of nine and shipped it. The panel deferral left the
  H-03 opening line, D-7's verdict row and its "my call", H-05's heading cost, and four
  spots in `magi-babel.html` — including a budget row titled *"H-03 panel"* — still
  saying H-03 owned the display. Caught only because I was asked whether I'd checked the
  HTML; it is hand-maintained with no generator, so nothing else would have. Pulling that
  thread found two older divergences: H-04 was ₹0 in the markdown against ₹5,500–7,000 in
  the HTML, and the by-phase budget row still said "1 TB SSD" after `PURCHASES.md`
  reversed it to a 2 TB HDD, counted RAM that belongs to H-08, and counted a switch the
  H-10 row four lines below counts again. Nothing ran badly; the failure was documentary.
- **Differently:** When a decision moves something between phases, grep the whole repo
  for it before committing, not just the section being edited — I fixed where I was
  looking and called it done. And verify a plan's claims at the phase that would act on
  them: `TOPICS.md` said H-03 needed an `mqtt2prometheus` bridge, which was true when
  written in H-02 and false by the time it mattered — node_exporter already exposes
  everything under `magi/sys/` at higher resolution (16 thermal sensors against one,
  plus battery and AC state). Building it would have added a container to duplicate data
  already there. Prometheus and the MQTT tree are parallel consumers of the same
  machine, not a pipeline.
