## 2026-09-03 · same day as H-02 closing
- **Did:** The whole software half of H-03 in one sitting. Metrics first — Prometheus,
  node_exporter, cAdvisor, Grafana on a new `glass` network, with Grafana and Prometheus
  also on `edge` so Caddy can serve them at `grafana.` and `prom.lab.akhildhyani.me`.
  node_exporter is the one container in the host network namespace, because `/proc/net`
  is per-namespace and a bridged exporter reports its own interfaces no matter how much
  of the host's `/proc` you mount at it. Then logs — Loki + Alloy (not Promtail, EOL
  March 2026), tailing both the docker socket and journald; the journal is the half that
  matters, since `magi-netaccess`'s portal retries and wpa_supplicant's slow PEAP
  association never appear in `docker logs`. Then Uptime Kuma, probing the *public*
  hostnames rather than container names, so it fails on a dead cert or a lapsed DNS
  delegation — things `magi-sys.py` cannot see. Datasources and dashboards provision
  from files (R1); two grafana.com dashboards committed with `__inputs` stripped and the
  datasource pinned to `uid: prometheus`. `whoami` retired, as H-03 said it would be.
- **Broke:** node_exporter's scrape timed out through two rounds of fixing. First cause:
  ufw's default-deny drops packets arriving from a docker bridge bound for the host, and
  *every layer looks fine in isolation* — the exporter logs "Listening on
  100.94.219.53:9100", `ss` shows the socket, `curl` from the host returns 200, ufw's own
  status shows nothing wrong. Second cause, mine: the rule I wrote named `br-glass`, but
  Prometheus is on both `glass` and `edge` and Docker routed it out `edge`, so the rule
  never matched. `[UFW BLOCK]` in the kernel log names the interface a packet actually
  arrived on and ended the argument in one line. Separately, pinning the Grafana
  datasource's uid crash-looped Grafana: provisioning cannot repoint an existing
  datasource at a new uid, and Grafana exits rather than run a half-applied config. And I
  put two errors into my own `MONITORS.md` — a probe target of `1.1.1.1`, which CLAUDE.md
  forbids precisely because on campus wifi that address is the DHCP server and the probe
  would pass while the portal was dead, and a Loki probe from a container that wasn't on
  `glass`.
- **Differently:** Set a provisioned uid before the first start, never after — changing
  one costs a crash loop and a `deleteDatasources` block. Before writing an
  interface-scoped firewall rule, check which network the container actually egresses
  from; a multi-homed container picks one and it may not be the one you had in mind. And
  reach for `journalctl -k | grep "UFW BLOCK"` first, not third: I spent two rounds
  reasoning about whether ufw or Tailscale's `ts-input` chain was responsible when one
  grep answered it.
