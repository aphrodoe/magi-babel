Phase log. Three lines per session: what I did, what broke, what I'd do differently.

## 2026-09-08 · ran from the evening of the 7th
- **Did:** Audited the eight-service list before building any of it, since the plan had
  never written down an alternative for anything except Pi-hole. Six survived unchanged.
  Two gaps: **the phase had no backup job in it** — R3 calls backups a plan, `TOPICS.md`
  reserves `magi/backup/{state,pct}`, H-05 has a BACKUP LED, and nothing actually ran
  `restic` — and no calendar, which is a bigger daily Google dependency than music.
  Added restic, Radicale and Karakeep; kept Navidrome on better evidence than it had
  (Jellyfin's Subsonic support is a community plugin, so the ~20 mature clients are
  second-class there). Then built: **Authelia** first and in front of Prometheus, the one
  service already up with no auth of its own; the **restic job** as a host systemd timer
  with a mountpoint guard, SQLite dumped through the backup API rather than copied, and
  `--prune` on Sundays only because the target is SMR; **AdGuard** with its config
  committed rather than clicked; **Radicale** for CalDAV/CardDAV. Neither of the last two
  sits behind Authelia — AdGuard has real auth already, and Radicale *must* keep HTTP
  Basic because CalDAV clients cannot follow a forward-auth redirect. The rule that fell
  out: **Authelia guards what has no auth of its own.**
- **Broke:** Two mistakes, both mine, both silent. I chose Quad9 over DoH reasoning that
  443 is hard to block, and never tested it on this network — every query timed out for
  30 s. Measured properly: the campus filters encrypted DNS **by provider, not by
  protocol**. Google's DoT works on 853 while Quad9's does not, on the same port; AdGuard's
  DoH endpoint works while Google's, Cloudflare's and Quad9's are blocked on 443. A TCP
  port check called 853 "open" the whole time, because a middlebox accepts the connection
  and then never completes the handshake. The same outage left AdGuard with **no blocklist
  at all** — it could not resolve the address its filter list downloads from — while the
  web UI served 200 throughout. Then the deploy script's username substitution matched
  `^    name: admin$` against a line that is really `  - name: admin`, two spaces and a
  dash because it is a YAML list item. It silently did nothing, the username stayed
  `admin`, and the only symptom was a 403 at the login page indistinguishable from a
  mistyped password — which sent the user to reset a credential that was never wrong.
- **Differently:** Measure the network before choosing an upstream; "443 is hard to block"
  is an assumption, not a property, on a filtered network. **A render step that can
  silently no-op needs a check that it did something** — I wrote exactly that guard into
  the backup job the same afternoon and then didn't apply it one script later. And monitor
  what a service *does*, not the port it listens on: an HTTP check on AdGuard would have
  been green through both failures, which is why its row in `MONITORS.md` is a DNS check
  and why there are now two of them — resolving and blocking fail separately.
