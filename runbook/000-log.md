## 2026-08-29 · third session
- **Did:** Wiped Windows off the HP and installed Ubuntu Server 26.04.1 LTS as `magi` —
  LVM without LUKS (a box on a shelf can't sit waiting at a passphrase prompt after a
  power cut), `ubuntu-lv` expanded to the full 466 G instead of the default 100 G.
  Pulled SSH keys with `ssh-import-id gh:aphrodoe`, installed Tailscale on both
  machines, ran the H-00 hardening script. `ssh magi` now works by name from cipher
  over the tailnet, key-only, on a direct peer-to-peer path — across campus wifi on one
  end and a phone tether on the other. **Verified an unattended reboot:** back in ~70 s
  with lid=ignore live, tailscaled/ssh/unattended-upgrades all active on their own and
  no failed units. Lid can be closed.
- **Broke:** `sudo tailscale up` on cipher hung silently with no error at all —
  Cloudflare WARP was holding the routing table. The standard advice (exclude
  100.64.0.0/10) did not apply: WARP already excluded it by default. The real failure
  was `tailscaled`'s control traffic to `*.tailscale.com` being dropped, because
  Tailscale fwmarks its own packets and WARP's policy routing discards marked packets.
  Fixed with `warp-cli tunnel host add tailscale.com` (+ `.io`); both VPNs now coexist.
  Smaller ones: the installer never got a DHCP lease off the phone tether even though
  the interface appeared (worked fine after reboot); campus wifi is WPA2-Enterprise so
  the installer's Edit Wifi can't express it; remote `sudo` over SSH needs `ssh -t`.
- **Differently:** Spent far too long fighting the installer's network screen.
  "Continue without network" was the right move from the start — the installed system
  has netplan, nmcli and real tools, and the only thing actually lost was the GitHub key
  import, which `ssh-import-id` did in one command two minutes later. Also should have
  checked cipher for an existing VPN *before* installing Tailscale on it.

## 2026-08-29 · fourth session
- **Did:** Settled MAGI's network. Probed the campus wall port with a purpose-built
  script (`scripts/magi/diag-net.sh`) and it is simply **open** — no 802.1X, no captive
  portal, no proxy, UDP passes, ~64 Mbps measured. Netplan now lives in the repo
  matching `en*`, so the USB-C ethernet adapter and a phone tether are interchangeable;
  installed by `scripts/magi/10-network.sh`, which backs up `/etc/netplan` and rolls
  back if no default route appears. Gave MAGI a read-only GitHub deploy key and cloned
  the repo to `~/homelab`, so the `git pull` half of the loop finally exists. Tested
  carrier loss for real by pulling the cable: DHCP re-acquired in 4 s on the same lease,
  Tailscale back in the same second — and it survived eight connector bounces on replug
  without wedging. Reorganised `scripts/` into `scripts/<host>/` with run-order prefixes.
- **Broke:** Masking the sleep targets last session silently broke upower.
  `CriticalPowerAction=HybridSleep` was pointing at a target that no longer exists, so
  on a power cut outlasting the battery MAGI would have attempted an impossible sleep
  and then hard-died at 0 % — an unclean shutdown on the box whose whole point is
  surviving power loss. Now `PowerOff`; hibernate was never an option since swap (4 G)
  is smaller than RAM (8 G). Separately, netplan's `optional: true` is **inert** here —
  it emits no `RequiredForOnline=no`, confirmed against the generated file — so boot
  would have stalled the full 120 s in `systemd-networkd-wait-online` whenever the
  switch was down, which is exactly the post-power-cut state. Capped at 20 s with
  `--any`. And my own probe miscounted EAPOL frames: `grep -c` prints `0` *and* exits 1,
  so the `|| echo 0` fallback appended a second line and broke the arithmetic test.
- **Differently:** Designed for the hard case before checking whether it existed — built
  a whole 802.1X-vs-captive-portal decision tree on the assumption that campus ethernet
  needs a login, and the port needed nothing. Probe first, then design. The wider lesson
  is from the upower bug: **every `systemctl mask` should be followed by asking what
  defaults were relying on that target.** Hardening is not free and it fails quietly.
