## 2026-08-29 · third session
- **Did:** Wiped Windows off the HP and installed Ubuntu Server 26.04.1 LTS as `magi` —
  LVM without LUKS (a box on a shelf can't sit waiting at a passphrase prompt after a
  power cut), `ubuntu-lv` expanded to the full 466 G instead of the default 100 G.
  Pulled SSH keys with `ssh-import-id gh:aphrodoe`, installed Tailscale on both
  machines, ran the H-00 hardening script. `ssh magi` now works by name from cipher
  over the tailnet, key-only, on a direct peer-to-peer path — across campus wifi on one
  end and a phone tether on the other. **Verified an unattended reboot:** back in ~70 s
  with lid=ignore live, tailscaled/ssh/unattended-upgrades all active on their own and
  no failed units. Lid can be closed.
- **Broke:** `sudo tailscale up` on cipher hung silently with no error at all —
  Cloudflare WARP was holding the routing table. The standard advice (exclude
  100.64.0.0/10) did not apply: WARP already excluded it by default. The real failure
  was `tailscaled`'s control traffic to `*.tailscale.com` being dropped, because
  Tailscale fwmarks its own packets and WARP's policy routing discards marked packets.
  Fixed with `warp-cli tunnel host add tailscale.com` (+ `.io`); both VPNs now coexist.
  Smaller ones: the installer never got a DHCP lease off the phone tether even though
  the interface appeared (worked fine after reboot); campus wifi is WPA2-Enterprise so
  the installer's Edit Wifi can't express it; remote `sudo` over SSH needs `ssh -t`.
- **Differently:** Spent far too long fighting the installer's network screen.
  "Continue without network" was the right move from the start — the installed system
  has netplan, nmcli and real tools, and the only thing actually lost was the GitHub key
  import, which `ssh-import-id` did in one command two minutes later. Also should have
  checked cipher for an existing VPN *before* installing Tailscale on it.
